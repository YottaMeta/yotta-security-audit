# 发现风险后的处置建议

本工具只读检测，不做修复。发现风险后按以下流程人工处置（需用户确认每一步）。

## 一、确认

1. 复看报告中的命中位置与证据，确认不是误报（上下文相关项尤其如此）。
2. 对照「威胁模式详解」判断属于哪类风险。
3. 必要时用 --json 导出结构化结果，并针对单个目录重扫核对。

## 二、隔离

对高风险技能（high / critical）：
1. 停止调用该技能，从智能体技能目录移出（移动到隔离目录或直接删除，需用户确认）。
2. 若已运行过其脚本，检查是否产生新进程、新启动项、新网络连接。
3. 若涉及凭据读取，建议轮换相关口令/令牌（SSH 密钥、云凭据、API 令牌、浏览器登录态）。

## 三、溯源

1. 记录来源：从哪里安装、作者、版本、更新历史。
2. 对比官方源与本地文件差异（哈希比对）。
3. 如确认恶意，可向所在平台举报（技能市场/仓库托管方）。

## 四、清理持久化

若报告命中持久化相关条目，在用户授权下：
1. 移除定时任务/启动项中新增的条目。
2. 检查 shell 配置文件与启动目录是否被写入。
3. 检查 Windows 注册表启动项与全局注入点是否被修改。

## 五、报告与复盘

1. 向用户说明：发生了什么、影响范围、已采取动作、后续建议。
2. 把经验沉淀到团队/项目知识库，避免同类风险再次发生。

## 法律与授权提醒

只对已获授权的主体执行以上操作。未经授权的检测与处置可能违反《网络安全法》与《刑法》285/286 条，后果由行为人自行承担。
